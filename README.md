## 동작 방식 (현재 파이프라인)

음성 한 번 → 로봇 4대의 명령 한 세트. 흐름은 다음과 같습니다.

1. **녹음** — 스페이스바를 누르고 있는 동안 마이크로 음성을 녹음한다.
2. **STT** — Groq Whisper(`whisper-large-v3-turbo`)로 한국어 음성을 텍스트로 전사한다.
3. **의도 분석** — 직전 의도(`prev_intent`)와 새 발화를 함께 입력해 `number`(인원), `situation`(상황), `activity`(행동), `furniture`(필요 가구), `posture`(자세: standing/sitting/lying)를 구조화 추출한다. **`number`와 `posture`는 대화 맥락이라 유지된다** — "테이블이 너무 작은데?" 같은 조정성 발화에서는 직전 값을 그대로 쓰고, 새로운 상황 발화이거나 누가 합류/이탈할 때만 바뀐다.
4. **행동 생성** — 의도 + 최근 history를 입력으로, 로봇 4대(L BOT 1·2, H BOT 1·2)의 명령(`active`, `furniture`, `size`, `x`, `y`)을 생성한다.
5. **검증** — `size`를 [0, 25, 50, 75, 100] 단계로 스냅하고, 위치 `(x, y)`를 정수 cm로 정규화해 배치 반경(200cm) 안으로 끌어들이며, 빈 라벨이면 inactive로 되돌린다. 마지막으로 **충돌 검사**로 두 로봇의 풋프린트가 겹치면 나중 로봇을 inactive로 내리는 결정론적 안전 검사를 거친다.
6. **history 저장** — 검증을 통과한 명령만 누적한다. **history의 가장 최근 항목이 곧 현재 로봇 4대의 상태**다.

LLM 응답이 실패하거나 깨지면 로봇이 멋대로 움직이지 않도록 **4대 모두 inactive 기본값**을 반환한다.

### 로봇 하드웨어 모델

| 축 | 설명 |
| --- | --- |
| 높이 (종류) | `L BOT`은 항상 낮고, `H BOT`은 항상 높다. size로 높이는 바뀌지 않는다. |
| size (0~100) | 윗면 형태를 결정. 0=좁고 평평, 중간(25·50·75)=가운데가 패인 그릇(작을수록 깊은 바구니, 클수록 넓고 얕은 트레이), 100=크고 평평한 원형 면(테이블). |
| 위치 (x, y) | 원점 `(0,0)`은 로봇 홈이 있는 구석, 사용자 중심은 `(120,100)`인 직교좌표. `x`가 클수록 사용자 기준 오른쪽, `y`가 클수록 앞이며 사용자는 `+y`(앞)를 바라본다. 같은 size라도 위치에 따라 의자·발받침대·협탁으로 의미가 갈린다. 윗면이 원형이라 회전(방향)은 의미가 없어 좌표만 쓴다. |

**가동 공간은 240cm(가로) × 200cm(세로)**. 원점 `(0,0)`을 로봇 홈 구석으로 두고 사용자는 그 중심 `(120,100)`에 선다 → 좌표 범위 `x ∈ [0, 240]`, `y ∈ [0, 200]`. 미사용(inactive) 로봇은 접힌 채 홈 `(0, 0)`에서 대기한다. **내부 계산은 모두 cm(정수)로 하고, 로봇에 보내는 최종 출력에서만 위치를 m 단위 float으로 변환**한다(예: `x=164cm → 1.64`). history는 cm로 유지된다.

로봇 실제 치수(가로×세로×높이, cm)와 그로부터의 반지름:

| 로봇 | size 0 | size 100 | 반지름(0→100) |
| --- | --- | --- | --- |
| H BOT | 41 × 41 × 70.5 | 72 × 72 × 70.5 | 20.5 → 36.0 |
| L BOT | 43 × 43 × 44.5 | 65 × 65 × 44.5 | 21.5 → 32.5 |

검증 레이어는 이 반지름으로 (1) 본체가 `[r, 크기−r]` 범위를 지켜 240×200 경계를 넘지 않게 좌표를 안으로 clamp하고, (2) 두 로봇 중심 거리가 반지름 합보다 작으면(파고들면) 나중 로봇을 접어 홈으로 보낸다. 정확히 맞닿는 정도는 허용하므로 복합 가구 연결(H BOT ×2 = 중심 72cm, L BOT ×2 = 65cm)은 통과한다.

**가용 재고는 L BOT 2대 + H BOT 2대, 총 4대뿐이다.** 가구가 더 필요해 보여도 이 4대를 초과할 수 없으며, 수요가 넘치면 우선순위를 정해 한정된 4대 안에서 최선의 조합을 구성한다.

로봇은 한 대씩 독립 가구로만 쓰는 게 아니라, **여러 대를 인접하게 붙여 하나의 복합 가구**로 합칠 수 있다. 예: `H BOT` 두 대를 size 100으로 양옆에 붙이면 다인용 대형 테이블, `L BOT` 두 대를 size 100으로 붙이면 침대처럼 넓은 평면이 된다. 정해진 조합 목록은 없고, 인원·상황에 맞는 새 조합도 자유롭게 구성한다. 충돌 검증은 **본체 바닥** 기준이라 윗면(상판)끼리 맞닿는 의도적 연결은 허용하고, 같은 자리에 포개지는 것만 막는다. 또한 **`number`(인원)가 클수록 더 넓은 면적·좌석이 필요한데, 이때 `size`를 올리는 게 아니라 로봇 대수를 늘리거나 연결해 넓힌다** — `size`는 인원 비례 값이 아니라 형태(용도)를 고르는 값이기 때문이다.

## 로드맵 (개발 현황)

이 프로젝트는 다음 세 방향으로 발전 중입니다.

### 1. 위치 스키마 추가 — *완료*
`size`에 더해 **중심점 (0,0)을 기준으로 가구를 위치 좌표 `(x, y)`에 배치**하는 축을 추가했다.
- (0,0)은 사용자 위치라기보다 **가구 세트를 배치할 중심점**이다. 이 중심을 기준으로 앞·뒤·좌·우를 구분한다. `x`=좌(-)/우(+), `y`=앞(+)/뒤(-), 단위 cm.
- 위치까지 결정되면 "같은 로봇이 위치에 따라 의자/발받침대/협탁이 된다"가 라벨이 아니라 **좌표에서 자연스럽게 유도**된다.
- 로봇 윗면이 원형이라 회전(yaw)은 형태에 영향을 주지 않으므로 방향 축은 두지 않고 좌표만 쓴다.
- **충돌·도달가능성 검증 레이어**를 결정론적 검사로 추가: 좌표를 배치 반경(200cm) 안으로 정규화하고, 두 로봇의 풋프린트(size 기반 반경)가 겹치면 우선순위가 낮은 로봇을 inactive로 내려 물리적 겹침을 차단한다. 안전 검증은 LLM이 아니라 코드가 최종 책임진다.

### 2. LLM Agent 전환 + LangSmith 트레이싱 — *예정*
현재의 단순 LLM 호출 방식을 **tool을 호출할 수 있는 에이전트 방식**으로 전환하고, **LangSmith**에 연결해 코드 흐름·추론 과정을 추적한다.
- 안전·충돌·재고 검증은 에이전트가 아니라 **결정론적 레이어가 최종 책임**진다.
- 실시간 제어인 만큼 지연·비결정성을 관리한다(하이브리드 구성 검토).

### 3. 라이브러리 + 툴 구축 — *예정*
에이전트가 참고/점검할 수 있는 지식 라이브러리와 조회 툴을 만든다.
- `furniture_mapping`: 활동 → 적절한 가구 조합 기준표(예: 독서 = 높은 카트 + 의자, 식사 = 큰 테이블 + 의자 여러 개). 강제 규칙이 아닌 **참고용 retrieval**로 두어 자유 라벨 철학을 유지한다.
- 위치 라이브러리: 신체 구역/방향 → 좌표 변환.
- 그 외 재고 조회, 현재 상태 조회, 레이아웃 검증 등 툴.
- 지식(데이터, JSON/YAML)과 툴(함수)을 분리해 git에서 버전 관리하기 쉽게 한다.

> 에이전트 도입으로 비결정성이 생기므로, **발화 → 기대 배치 평가셋**을 만들어 변경 시 회귀를 점검할 예정.
